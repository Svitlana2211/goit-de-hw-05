# Домашнє завдання №5 — Apache Kafka

Система моніторингу температури та вологості датчиків будівель.
Реалізована мовою Python із використанням kafka-python.

## Файли проєкту

- `create_topics.py` — створення трьох топіків.
- `producer.py` — генерація та надсилання показників одного датчика.
- `processor.py` — читання показників, перевірка порогів і запис сповіщень.
- `alerts_consumer.py` — читання сповіщень із двох топіків.
- `configs.example.py` — приклад налаштувань підключення без пароля.
- `requirements.txt` — бібліотеки для встановлення.

## Топіки

- `svitlana_mishuhli_building_sensors`
- `svitlana_mishuhli_temperature_alerts`
- `svitlana_mishuhli_humidity_alerts`

## Логіка роботи

Один запуск `producer.py` відповідає одному датчику.
Ідентифікатор датчика залишається незмінним протягом запуску.

Кожні 2 секунди датчик надсилає:
- ідентифікатор;
- час вимірювання у форматі UTC;
- температуру від 25 до 45 °C;
- вологість від 15 до 85 %.

Обробник створює сповіщення:
- якщо температура перевищує 40 °C;
- якщо вологість нижча за 20 % або вища за 80 %.

Сповіщення містить дані вимірювання, пояснення та позицію
початкового запису в Kafka.

## Підготовка після завантаження проєкту

Потрібні Python 3.12 та доступ до навчального сервера Kafka.

Створити й активувати середовище:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Створити робочий файл налаштувань зі зразка:

```bash
cp configs.example.py configs.py
```

У `configs.py` замінити `YOUR_KAFKA_PASSWORD` на пароль
навчального сервера з матеріалів курсу.

Файл `configs.py` із паролем виключено з Git через `.gitignore`.

## Запуск

Створити топіки:

```bash
.venv/bin/python create_topics.py
```

В окремому терміналі запустити обробник:

```bash
.venv/bin/python processor.py
```

В іншому терміналі запустити читання сповіщень:

```bash
.venv/bin/python alerts_consumer.py
```

У двох додаткових терміналах виконати однакову команду:

```bash
.venv/bin/python producer.py
```

Два запуски створять два датчики з різними ідентифікаторами.
Для зупинки кожної програми натиснути Ctrl+C в її терміналі.

Обробник також може прочитати вже надіслані показники після
зупинки датчиків, доки ці дані зберігаються в Kafka.

## Перевірка виконання

Під час перевірки:
- створено три топіки;
- запущено два датчики одночасно;
- виконано фільтрацію показників;
- записано сповіщення у відповідні топіки;
- прочитано 31 сповіщення про температуру та 12 про вологість.

Ці кількості стосуються проведеного запуску.
За нового запуску результати залежать від випадкових показників.

Групи споживачів зберігають позицію читання.
Повторний запуск продовжує читання зі збереженої позиції.
Для повторного перегляду попередніх сповіщень можна змінити
`group_id` у `alerts_consumer.py` на нове унікальне значення.

Скриншоти виконання та короткі пояснення наведено у звіті.
